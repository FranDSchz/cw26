# Protocolo de estudio técnico

## Objetivo

Mantener una preparación intensa, pedagógicamente sólida y orientada a las capacidades necesarias para competir en un Attack/Defense CTF, evitando tanto el aprendizaje superficial como las desviaciones que retrasan el plan.

## Regla 80/20

Cada módulo utiliza aproximadamente:

- **80 % del tiempo:** objetivo obligatorio, laboratorio, entregable y criterio de aprobación.
- **20 % del tiempo:** profundización, recursos complementarios, preguntas derivadas y mejora de comprensión.

La profundización no puede impedir que se complete el entregable principal.

Si el 80 % obligatorio todavía no está resuelto, una desviación solo continúa cuando es un prerrequisito real para comprender, ejecutar o recuperar el laboratorio.

## Cuándo profundizar inmediatamente

Una duda debe resolverse durante la sesión cuando no comprenderla pueda provocar:

- ejecutar comandos peligrosos sin entenderlos;
- perder o corromper datos;
- aplicar un parche inseguro;
- interpretar incorrectamente un resultado;
- no poder diagnosticar un fallo;
- no poder repetir el procedimiento sin ayuda;
- no comprender un concepto central del módulo;
- construir una base incorrecta para los temas siguientes.

La explicación debe alcanzar el nivel necesario para continuar con seguridad y autonomía. No es obligatorio estudiar en profundidad todos los detalles internos.

## Cuándo utilizar el Parking Lot

Una duda se aplaza cuando corresponde a:

- detalles internos que no afectan el objetivo actual;
- historia o teoría sin transferencia inmediata;
- herramientas alternativas;
- optimizaciones avanzadas;
- variantes que no forman parte del criterio de aprobación;
- contenido interesante pero no prioritario;
- temas que pertenecen a un módulo posterior.

Formato:

PARKING LOT:

- Tema:
- Por qué apareció:
- Impacto posible:
- Momento recomendado para retomarlo:

El Parking Lot se revisa durante el cierre del módulo o la planificación semanal. No se utiliza para ocultar prerrequisitos importantes.

## Regla de bloqueo

- Hasta 10 minutos: intentar, observar errores y consultar ayuda local.
- A los 10–25 minutos: revisar documentación concreta o pedir una pista.
- A los 25 minutos: escalar, hacer pairing o cambiar temporalmente de enfoque.
- A los 45 minutos de bloqueo grupal: volver al último estado conocido como bueno y registrar el incidente.

No se permite perder horas intentando resolver silenciosamente un problema sin producir nueva evidencia.

## Uso de recursos complementarios

El PDF o plan diario define objetivos, prioridades, entregables y criterios de aprobación, pero no constituye un guion pedagógico rígido.

El tutor puede:

- cambiar el orden interno del contenido;
- reemplazar un recurso por otro mejor;
- agregar una explicación propia;
- diseñar otro laboratorio;
- reducir contenido redundante;
- dividir un salto pedagógico demasiado grande.

Todo recurso adicional debe indicar:

- qué problema resuelve;
- qué sección exacta utilizar;
- cuánto tiempo dedicar;
- qué evidencia producir;
- por qué mejora el recurso original.

No se agregan listas extensas de cursos, videos o artículos sin una función concreta.

## Forma de aprendizaje

La secuencia preferida es:

1. Construir el modelo mental mínimo.
2. Formular una hipótesis.
3. Ejecutar una práctica guiada.
4. Observar e interpretar el resultado.
5. Resolver una variante con menos ayuda.
6. Repetir la parte crítica sin guía.
7. Registrar evidencia, tiempo, errores y recuperación.
8. Explicar con palabras propias lo aprendido.

No se considera aprendido un tema solamente por haber leído, visto un video o copiado comandos.

## Criterio de aprendizaje demostrado

Una habilidad se considera demostrada cuando la persona puede:

- explicar qué está haciendo;
- ejecutar el procedimiento;
- interpretar el resultado;
- reconocer un fallo;
- recuperar o corregir una variante;
- repetir la parte crítica con poca o ninguna ayuda;
- producir evidencia reproducible.

## Control de tareas

Cada persona mantiene:

- una tarea técnica principal;
- como máximo una extensión preparada.

No se inicia un tema nuevo importante mientras el entregable principal permanezca incompleto, salvo que exista una decisión explícita de replanificación.

## Control del atraso

El atraso no se recupera acumulando mecánicamente jornadas completas.

Cuando existe un desvío:

1. Registrar el estado técnico real.
2. Identificar capacidades completadas y pendientes.
3. Eliminar repeticiones innecesarias.
4. Mantener las dependencias pedagógicas.
5. Rebasar el calendario desde el estado actual.
6. Priorizar gates y entregables sobre fechas históricas.
7. Evitar compensar con una madrugada que comprometa el día siguiente.

La métrica principal es capacidad adquirida, no cantidad de fechas tachadas.

## Sueño y cierre

No se inicia un módulo técnico nuevo cuando:

- la energía es 2/5 o menor;
- hay errores operativos crecientes;
- se alcanzó el horario de cierre acordado;
- continuar comprometería el sueño mínimo de la jornada siguiente.

En esas condiciones solo se permite:

- registrar evidencia;
- cerrar tareas;
- preparar el próximo inicio;
- actualizar documentación;
- realizar una revisión breve.

## Gestión de chats técnicos

Se utiliza un chat por módulo técnico coherente, no necesariamente uno por día.

Un chat se jubila cuando:

- el entregable principal está cerrado;
- comienza una capacidad técnica distinta;
- el contexto acumulado produce confusión;
- existen demasiadas ramas secundarias;
- el tutor ya produjo el paquete de cierre.

Antes de jubilarlo debe producir:

1. Apunte conceptual.
2. Estado operativo.
3. Datos para actualizar el control.
4. Parking Lot.
5. Prompt de traspaso.
6. Próxima acción exacta.

## Autonomía del tutor

El tutor debe ser dinámico y adaptar la enseñanza a los errores, conocimientos y ritmo observados.

Puede apartarse del orden original cuando exista una razón pedagógica clara, pero debe conservar:

- el objetivo del módulo;
- la transferencia a Attack/Defense;
- los entregables;
- los criterios de aprobación;
- el control del tiempo;
- la producción de evidencia.

No debe convertir la sesión en una estructura burocrática ni en una exploración abierta sin prioridades.
